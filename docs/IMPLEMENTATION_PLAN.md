# 과제 1 구현 순서

## 브랜치 운영 기준

- `main`: 제출 가능한 최종 코드
- `DEV`: 기능을 합치고 확인하는 통합 브랜치
- 작업 브랜치: 각 단계의 코드를 작성하는 브랜치
- 각 작업 브랜치는 `DEV`에서 생성하고, 작업이 끝나면 `DEV`에 합친다.
- 모든 기능이 완성되면 마지막에 `DEV`를 `main`에 합친다.

## 1. 기본 앱 구조

**브랜치:** `feature/app-shell`

### 작업 내용

- 기능별 폴더 생성
- `main.dart`에서 앱 실행
- 앱 테마와 첫 화면 구성
- 관심 화면과 검색 화면을 전환하는 하단 내비게이션 구현
- 회사에서 제공한 디자인 토큰 연결

### 실행 흐름

```text
main.dart
  -> app/app.dart
  -> app/app_controller.dart
  -> 관심 화면 또는 검색 화면
```

### 완료 기준

- 앱을 실행하면 관심 화면이 표시된다.
- 하단 탭을 누르면 관심 화면과 검색 화면이 전환된다.
- 화면에서 회사 제공 테마를 사용한다.

## 2. 공통 데이터 모델

**브랜치:** `feature/stock-models`

### 작업 내용

- `Stock` 모델 작성
- `StockQuote` 모델 작성
- `StockDetail` 모델 작성
- `DailyPrice` 모델 작성
- 검색, 메타데이터, 실시간 시세 DTO 작성
- DTO가 Naver 응답을 읽고 앱 모델로 변환하도록 구성

### 실행 흐름

```text
Naver 응답
  -> data의 DTO
  -> 앱 데이터 모델
  -> controller와 화면에서 사용
```

### 완료 기준

- 화면에서 Naver의 JSON 필드명을 직접 사용하지 않는다.
- 앱 모델에서 Naver의 JSON 필드명을 직접 사용하지 않는다.
- 종목, 현재가, 상세 정보, 일봉 데이터의 역할이 구분된다.

## 3. 검색 기능

**브랜치:** `feature/stock-search`

### 작업 내용

- 검색 화면 UI 구현
- Naver 종목 검색 API 연결
- 종목명과 6자리 종목 코드 검색
- 검색 전 안내 상태 구현
- 검색 결과 목록 구현
- 검색 결과 없음 상태 구현
- 검색어 강조 표시
- 검색 입력 지연 처리
- 이전 요청보다 최신 검색 요청만 화면에 반영

### 실행 흐름

```text
사용자 검색어 입력
  -> search_controller
  -> naver_stock_service
  -> Naver 검색 API
  -> List<Stock>
  -> search_controller 상태 갱신
  -> 검색 화면 갱신
```

### 완료 기준

- 검색어가 없으면 검색 안내 화면이 표시된다.
- 정상 검색 시 국내 주식 목록이 표시된다.
- 일치하는 결과가 없으면 결과 없음 화면이 표시된다.

## 4. 관심 종목 공통 상태와 저장

**브랜치:** `feature/favorites`

### 작업 내용

- 관심 종목 코드 목록 관리
- 별 버튼으로 관심 등록 및 해제
- 검색 화면과 상세 화면에서 같은 관심 상태 공유
- 관심 등록 및 해제 토스트 표시
- `shared_preferences`에 관심 종목 코드 목록 저장
- 앱 시작 시 저장된 관심 종목 코드 복원

### 실행 흐름

```text
별 버튼 선택
  -> 관심 상태 변경
  -> favorite_storage에 종목 코드 저장
  -> 연결된 화면 갱신
  -> 등록 또는 해제 토스트 표시
```

### 완료 기준

- 한 화면에서 변경한 별 상태가 다른 화면에도 반영된다.
- 앱을 종료하고 다시 실행해도 관심 종목이 유지된다.
- 종목 코드가 중복 저장되지 않는다.

## 5. 관심 화면

**브랜치:** `feature/watchlist`

### 작업 내용

- 관심 종목 빈 상태 구현
- 관심 종목 목록 구현
- 여러 종목의 실시간 시세 일괄 조회
- 종목별 시세 로딩 스켈레톤 구현
- 현재가순, 등락률순, 가나다순 정렬
- 정렬 Bottom Sheet 구현
- 새로고침 구현

### 실행 흐름

```text
저장된 관심 종목 코드 불러오기
  -> watchlist_controller
  -> naver_stock_service의 시세 일괄 조회
  -> Map<String, StockQuote>
  -> 정렬 적용
  -> 관심 목록 화면 갱신
```

### 완료 기준

- 관심 종목이 없으면 빈 상태가 표시된다.
- 관심 종목이 있으면 최신 시세와 함께 표시된다.
- 정렬 방식 변경과 새로고침이 동작한다.
- 일부 종목의 시세가 누락되어도 나머지 목록은 표시된다.

## 6. 종목 상세 화면

**브랜치:** `feature/stock-detail`

### 작업 내용

- 검색 결과와 관심 목록에서 상세 화면으로 이동
- 뒤로 가기와 종목 기본 정보 표시
- 상세 화면의 관심 버튼 연결
- 현재가, 전일 대비, 등락률 표시
- 시가, 고가, 저가, 거래량, 시가총액 표시
- 상세 정보 로딩 및 오류 상태 구현

### 실행 흐름

```text
종목 행 선택
  -> 종목 코드를 상세 화면에 전달
  -> stock_detail_controller
  -> Naver 상세 및 시세 API
  -> StockDetail과 StockQuote
  -> 상세 화면 갱신
```

### 완료 기준

- 관심 화면과 검색 화면에서 같은 상세 화면으로 이동한다.
- 전달받은 종목 코드에 맞는 정보가 표시된다.
- 상세 화면에서도 관심 등록 및 해제가 가능하다.

## 7. 차트와 일별 시세

**브랜치:** `feature/price-chart`

### 작업 내용

- 1개월, 3개월, 6개월, 1년 기간 선택
- Naver 일봉 데이터 조회
- 일봉 HTML 문자 인코딩 변환
- 기간에 필요한 페이지 수만큼 조회
- 캔들 차트 구현
- 일별 시세 목록 구현
- 종목 코드와 기간을 기준으로 메모리 캐시 적용

### 실행 흐름

```text
기간 선택
  -> stock_detail_controller
  -> 메모리 캐시 확인
  -> 캐시가 없으면 Naver 일봉 조회
  -> List<DailyPrice>
  -> 차트와 일별 시세 화면 갱신
```

### 완료 기준

- 기간을 선택하면 해당 기간의 데이터가 표시된다.
- 같은 종목과 기간을 다시 선택하면 캐시를 사용한다.
- 차트는 과거부터 최신 순서로 표시된다.
- 일별 시세는 최신 날짜부터 표시된다.

## 8. 예외 상태와 화면 보완

**브랜치:** `fix/edge-cases`

### 작업 내용

- 네트워크 오류 메시지 정리
- 일부 데이터 실패 처리
- 중복 API 요청 방지
- 긴 종목명과 작은 화면의 넘침 처리
- 빠른 탭 전환과 연속 입력 처리
- 로딩, 빈 상태, 오류 상태의 디자인 통일

### 완료 기준

- API 실패로 앱이 종료되지 않는다.
- 일부 데이터가 실패해도 정상 데이터는 유지된다.
- 긴 텍스트가 화면 밖으로 넘치지 않는다.
- 상태별 화면이 Figma와 일관된 형태로 표시된다.
