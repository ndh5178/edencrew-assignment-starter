# 데이터 조회 개선

## 변경 내용

- 검색 결과는 검색어별로 5분간 최대 30개 보관한다. 같은 검색어를 다시 입력하면 디바운스와 통신 없이 표시한다. 보관 한도를 넘으면 최근에 사용하지 않은 항목부터 제거한다.
- 검색 확정 시 350ms 타이머를 취소하고 즉시 요청한다. 동일 검색어의 진행 중 요청은 공유하고, 요청 실패는 캐시하지 않는다.
- 관심 목록의 메타데이터와 시세는 종목 코드만으로 각각 요청할 수 있어 동시에 시작한다. 메타데이터 완료 후에는 시세를 기다리는 행을 표시한다.
- 일봉 페이지의 Future를 종목·응답 형식·페이지별로 공유한다. 완료된 결과뿐 아니라 진행 중인 요청도 재사용한다. 실패한 페이지는 제거하여 재시도할 수 있다.
- 일봉 페이지는 종목별 5분 세션으로 보관하고 최대 20종목으로 제한한다. 기간별 UI 캐시도 5분 후 폐기한다. 현재가 조회에는 이 캐시를 적용하지 않는다.
- 캐시된 기간으로 돌아올 때도 요청 번호를 갱신하여 이전 기간 응답이 현재 차트를 덮어쓰지 못하게 한다.

## 검증과 해석

- 동일 검색어 재검색: 추가 서비스 호출 0회, 상태를 즉시 success로 전환하는 테스트.
- 1개월(2페이지)과 3개월(6페이지) 동시 조회: HTML 정상 응답 조건에서 전체 페이지 요청 8회 대신 6회, 각 페이지 1회. 이후 1개월 조회는 추가 요청 0회.
- 캐시된 1개월로 돌아온 후 도착한 3개월 응답은 반영하지 않는 회귀 테스트.
- 메타데이터 응답을 보류한 상태에서도 시세 요청이 시작되는 테스트.

위 수치는 제어된 테스트의 요청 횟수다. 실제 Naver 서버 응답 시간 개선율은 측정하지 않았다. HTML 실패 시 JSON으로 넘어가는 요청은 별도로 발생할 수 있다.

## 정책과 남은 절충점

최초 검색은 350ms 입력 대기와 네트워크 지연이 남는다. 검색 결과는 최대 5분 오래될 수 있지만 가격은 포함하지 않는다. 일봉 세션은 페이지별 독립 만료 대신 같은 만료 시점을 사용하며, 새 거래일이나 장중 데이터 변화는 다음 세션에서 반영한다. 서버는 조회 중에도 변할 수 있으므로 캐시는 서버 데이터의 원자적 스냅샷을 보장하지 않는다.

페이지는 순차적으로 필요한 만큼만 읽는다. 전체 페이지 병렬 요청이나 프리패치는 서버 호출 부담과 마지막 페이지 처리를 고려해 도입하지 않았다. 오래된 화면 응답을 무시하는 것은 실제 HTTP 요청 취소와는 다르다.
